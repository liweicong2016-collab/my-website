四大 Agent 架构与 42 步案例：办公、编程、视频与个人助理

用可交互的架构图和具体任务步骤，理解四类 Agent 各自的工作机制

办公、编程、视频和个人助理都可以采用模型、工具与记忆组成的 Agent 基础能力。但从具体任务出发，四类系统需要保存的状态、执行环境和判断成功的方式有明显区别。

四类架构，四种工作机制

场景架构重心具体案例步骤数
办公组织权限与可恢复的业务流程跨部门会议及纪要协作10
编程仓库版本、隔离修改与真实验证修复无效令牌被误放行的接口10
视频分镜任务、参考资产与异步生成15 秒智能耳机广告12
个人情境、偏好、授权与操作核对周末杭州两日游10

办公 Agent 的核心是把跨系统业务流程协调完整。它需要知道谁可以访问什么材料、哪一步需要审批，以及接口超时后是否已经产生业务结果。流程状态、幂等和补偿为恢复任务提供基础。

编程 Agent 的核心是让修改与证据对应。理解仓库、保留起始版本、在独立工作区修改，再运行真正的构建和测试。失败时要分清代码错误、环境问题与已有失败，通过后才能形成可评审变更。

视频 Agent 的核心是组织镜头级生产。创意要被转成有编号、时长和参考资产的分镜任务；独立镜头可以并行，失败镜头可以局部重做。素材版本和时间轴把图像、视频、音乐与字幕汇成可验收的成片。

个人 Agent 的核心是把个性化服务做可信。它要区分明确指令和历史偏好，依据当前情境做计划，在已有授权内执行，并核对真实结果。长期记忆需要可查看、可修改、可删除，主动提醒要遵守授权与通知规则。

四个完整案例

以下均为教学示例。价格、时段和任务结果不是实时查询或已经执行的记录。架构是场景规划，不是对商业产品内部实现的披露；MCP 是可选连接方式，实际系统也可通过原生 API 或应用自动化接入。

办公 Agent · 案例：安排跨部门评审会，并分发会议纪要（10 步）

步骤动作
Step 1理解任务 — 本周组织三部门评审会，30 分钟，提前发送材料。
Step 2读取组织与权限 — 查询三位负责人身份，只检索请求人有权访问的项目材料。
Step 3查询可用时段 — 三人共同空闲时间为周四 14:00–14:30。
Step 4编排任务依赖 — 先确认时段，再预订会议室，随后发送邀请与附件。
Step 5处理必要审批 — 若会议室需要负责人审批，保存流程状态并等待回复。
Step 6执行预约与通知 — 预约会议室 A，发送邀请；同一请求使用幂等键。
Step 7核对实际结果 — 通知接口超时后先查发送记录，再决定是否重试。
Step 8整理会议纪要 — 依据会议材料记录决策、负责人、期限。
Step 9校验并按授权分发 — 核对纪要与原始记录，将确认版本发送给参会人。
Step 10汇总与更新状态 — 报告会议安排、纪要链接、完成项及仍需人工处理的事项。

编程 Agent · 案例：修复无效令牌被误放行的登录接口（10 步）

步骤动作
Step 1明确验收条件 — 无效令牌返回 401；有效令牌访问接口仍返回 200。
Step 2记录仓库基线 — 记录起始提交和已有修改，在独立工作区进行任务操作。
Step 3检索认证调用链 — 定位 auth 中间件、令牌校验函数和对应测试。
Step 4复现并确认原因 — 校验异常被捕获后仍调用 next()，导致错误放行。
Step 5设计最小修复 — 异常分支返回 401 并终止处理，保留有效令牌的正常路径。
Step 6应用补丁与回归用例 — 修改异常处理，同时新增「无效令牌拒绝访问」的测试。
Step 7运行真实验证 — 执行认证相关测试，再运行修改范围对应的构建与检查。
Step 8分析失败并重修 — 若有效令牌测试也失败，检查修复是否错误截断正常分支。
Step 9检查差异和证据 — 确认补丁未覆盖无关修改，验证结果对应最终代码版本。
Step 10准备 PR 与评审反馈 — PR 说明原因、修复行为及测试；CI 或评审反馈再进入修复循环。

视频 Agent · 案例：制作 15 秒科幻风格智能耳机广告（12 步）

步骤动作
Step 1明确制作规格 — 15 秒、16:9、卖点降噪与空间音效。
Step 2形成创意脚本 — 喧嚣都市 → 戴上耳机 → 宁静太空 → 产品落版。
Step 3拆分镜头与时长 — S1 都市 3s / S2 戴耳机 4s / S3 太空 5s / S4 落版 3s = 15s。
Step 4固定参考资产 — 黑色机身、银色标识、蓝紫灯光、同一人物参考图。
Step 5编写逐镜头生成输入 — 每镜头提示词、参考图、支持参数。
Step 6调度镜头生成 — 按依赖提交，独立镜头并行，记录任务 ID、预算、配额。
Step 7生成配音与音乐 — 配音 + 城市噪声转氛围音。
Step 8逐镜头质检与重生成 — 失败镜头局部重做。
Step 9组装画面时间轴 — 3/4/5/3 秒排列镜头，转场顺畅。
Step 10音画与字幕合成 — 字幕对齐太空镜头，结尾品牌名与卖点。
Step 11渲染并验收成片 — 导出 1920×1080，核对时长、画幅、产品外观、音画同步。
Step 12交付与保留制作记录 — 交付成片、分镜表、素材清单、生成参数。

个人 Agent · 案例：规划周末杭州两日游并设置提醒（10 步）

步骤动作
Step 1理解目标与约束 — 从上海出发，周末杭州两日游，预算 1500 元，少走路。
Step 2读取偏好与日程 — 读取明确保存的靠窗偏好，检查本周末是否已有其他安排。
Step 3查询车次、酒店与路线 — 查询往返车次、地铁附近酒店和西湖周边路线。
Step 4组合并核算方案 — 交通 300 + 酒店 500 + 餐饮 300 + 市内 150 = 1250 元。
Step 5检查授权与必要确认 — 已有授权内设置提醒；超出授权展示订单等待确认。
Step 6执行已授权操作 — 按确认方案预约车票或创建日历；无授权保留候选。
Step 7核对订单与防重复 — 提交超时后先查订单，确认成功再报告，避免重复预订。
Step 8创建出发提醒 — 在已授权日历中设置「出发前 60 分钟检查证件和乘车站」。
Step 9汇总行程和待办 — 提供两日路线、预算、订单状态，指出尚未完成的预订。
Step 10管理记忆与主动服务 — 用户确认后保存偏好；只按授权事件触发提醒。

从架构到建设

先完成一条可以核对结果的任务链，再扩大自动化范围：办公先验证一个跨系统流程，编程先修复一个真实缺陷，视频先制作一段可局部重做的短片，个人先完成一个明确指令。任务变复杂时，再增加执行器、连接器、并行调度或主动服务。

对每个任务，最后都要能说明产物在哪里、哪些步骤真正执行、哪些证据支持完成状态，以及仍有哪些待办或验证局限。
